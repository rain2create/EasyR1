# 多模态数据流详解

## 一、多模态消息格式

### 为什么要分开构建？

多模态必须把文本和图像分开构建，这是多模态模型的标准格式。

**纯文本格式：**
```python
messages = [
    {"role": "user", "content": "What is 2+2?"}  # 一个字符串
]
```

**多模态格式：**
```python
messages = [
    {"role": "user", "content": [
        {"type": "text", "text": "What shape is shown in "},
        {"type": "image"},                          # 图像标记
        {"type": "text", "text": "?"}
    ]}
]
```

### 为什么分开？

因为 processor 需要知道图像插入的位置：

```
原始问题: "What shape is shown in <image>?"
                ↓ 拆分
["What shape is shown in ", "<image>", "?"]
                ↓ 构建消息
content = [
    {"type": "text", "text": "What shape is shown in "},
    {"type": "image"},   ← 图像会插到这里
    {"type": "text", "text": "?"}
]
                ↓ processor 处理
input_ids: [文本tokens, <|image_pad|>, <|image_pad|>, ..., 文本tokens]
                           ↑ 图像占位符
```

**简单说：分开构建是为了告诉模型"图像插在文本的哪个位置"。**

## 二、图像预处理 (Step 4)

### 目的：把图像调整到合适的尺寸

```python
# 原始图像可能是任意大小
原图: 4000 x 3000 像素 = 12,000,000 pixels (太大！)

# 限制范围
min_pixels = 262144   (512×512)
max_pixels = 4194304  (2048×2048)

# 调整后
处理后: 1024 x 768 像素 ≈ 786,432 pixels (合适)
```

### 为什么要限制？

| 太大 | 太小 |
|-----|------|
| 显存爆炸 | 图像模糊，看不清 |
| 计算太慢 | 细节丢失 |

## 三、Processor 处理 (Step 5)

### Processor 是什么？

Processor 是 HuggingFace 的多模态处理器，包含两部分：

```python
from transformers import Qwen2VLProcessor

processor = Qwen2VLProcessor.from_pretrained("Qwen/Qwen2-VL-7B")

# 它包含两部分：
processor.tokenizer        # 文本 tokenizer
processor.image_processor   # 图像处理器
```

### 目的：把图像和文本转成模型能吃的数字

```
输入:
  - PIL.Image (图像)
  - prompt (文本)

输出:
  - input_ids: 文本 + 图像占位符 的 token 序列
  - pixel_values: 图像的特征向量
  - image_grid_thw: 图像网格尺寸
```

---

## 四、为什么要切成小块 (Patches)？

### Vision Transformer (ViT) 的核心设计

```
传统 CNN: 整张图 → 卷积 → 特征
    ↓
ViT 思路: 图像 → 切成 patches → 每个 patch 当成一个"词"
```

### 类比理解

| 文本处理 | 图像处理 |
|---------|---------|
| 句子切成 words | 图像切成 patches |
| 每个 word → embedding | 每个 patch → embedding |
| word 序列进 Transformer | patch 序列进 Transformer |

```
图像: 392 × 392 像素
     ↓ 切成 14×14 的小块
patches: (392/14) × (392/14) = 28 × 28 = 784 个
```

## 五、为什么 pixel_values 是 (784, 1280)？

### 数字含义

| 数字 | 含义 | 怎么来的 |
|-----|------|---------|
| **784** | patch 数量 | 图像大小 / patch大小² = 28×28 |
| **1280** | 每个patch的向量维度 | 模型 hidden_size（7B模型） |

### 计算示例

```python
# 图像 392×392，patch 大小 14×14
image_size = 392
patch_size = 14

num_patches_h = 392 / 14 = 28  # 高度方向 28 个 patch
num_patches_w = 392 / 14 = 28  # 宽度方向 28 个 patch
num_patches = 28 * 28 = 784    # 总共 784 个

# 每个patch 展平后投影到 hidden_size
patch_pixels = 14 * 14 * 3 = 588  # 每个patch 588 个像素
embedding_dim = 1280              # 投影到 1280 维（模型配置）
```

### 直观图示

```
原图 392×392×3
      ↓
┌─────────────────────────────┐
│ p1  p2  p3  ... p28         │
│ p29 p30 p31 ... p56         │  每个 pi 是 14×14×3 的小块
│ ...                         │
│ p757...p784                 │
└─────────────────────────────┘
      ↓ 每个 patch 投影
[p1_vec, p2_vec, ..., p784_vec]  每个是 1280 维向量

最终: pixel_values shape = (784, 1280)
```

**一句话：图像切成 784 个 patch，每个 patch 变成 1280 维向量，这样图像就能像文本一样进 Transformer 处理。**

## 六、整体流程总结

```
Step 4: 图像预处理
┌─────────────┐
│  原图 JPG   │  任意大小
└─────────────┘
       ↓ 调整尺寸 (min_pixels ~ max_pixels)
┌─────────────┐
│  PIL.Image  │  392×392×3
└─────────────┘

Step 5: Processor 处理
┌─────────────┐     ┌─────────────┐
│  PIL.Image  │     │   prompt    │
└─────────────┘     └─────────────┘
       ↓                   ↓
┌─────────────┐     ┌─────────────┐
│ image_processor    │  tokenizer  │
│ 切patch+投影       │  文本分词    │
└─────────────┘     └─────────────┘
       ↓                   ↓
┌─────────────┐     ┌─────────────┐
│pixel_values │     │ input_ids   │
│ (784, 1280) │     │ + 占位符    │
└─────────────┘     └─────────────┘
       └───────────┬───────────┘
                   ↓
           送入 Transformer 模型
```

## 七、vLLM 和 Tokenizer 的关系

### vLLM 是推理引擎，不是 tokenizer

```
┌─────────────────────────────────────────────────────┐
│                    vLLM                              │
│  (高性能推理引擎，优化 KV Cache、PagedAttention 等)   │
│                                                      │
│   内部使用:                                          │
│   - HuggingFace tokenizer (文本)                    │
│   - HuggingFace image_processor (图像)              │
│   - 或者 Processor (封装了上面两个)                  │
└─────────────────────────────────────────────────────┘
```

### Processor = Tokenizer + ImageProcessor

```python
# Processor 包含 tokenizer
processor = Qwen2VLProcessor.from_pretrained("Qwen/Qwen2-VL-7B")

# 等价于
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2-VL-7B")
image_processor = AutoImageProcessor.from_pretrained("Qwen/Qwen2-VL-7B")

# Processor 内部调用
processor.tokenizer(text)           # 文本 → tokens
processor.image_processor(images)  # 图像 → pixel_values
```

### 所以 Processor 就是多模态版的 Tokenizer

| 组件 | 文本输入 | 图像输入 | 输出 |
|-----|---------|---------|------|
| Tokenizer | ✓ | ✗ | input_ids |
| ImageProcessor | ✗ | ✓ | pixel_values |
| **Processor** | ✓ | ✓ | input_ids + pixel_values |

**Processor = Tokenizer + ImageProcessor，负责把文本和图像都变成模型能理解的数字。**
