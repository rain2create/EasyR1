# Worker (FSDP+TP) 工作流详解

> 本文档详细解释 Driver → Worker → GPU 的数据分配流程，以及各组件的职责边界。

---

## 一、场景设置

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           场景配置                                           │
└─────────────────────────────────────────────────────────────────────────────┘

硬件配置：
  - 2 台机器
  - 每台机器 8 张 GPU
  - 共 16 张 GPU

Worker 配置：
  - 2 个 Worker（每台机器一个 Worker 进程）
  - 每个 Worker 管理 8 张 GPU

训练配置：
  - rollout_batch_size = 128           # 最终需要多少个不同的"问题"
  - mini_rollout_batch_size = 32       # DataLoader 每次取多少个 prompt
  - rollout.n = 8                      # 每个 prompt 生成几个回答（GRPO需要 n>1）
  - global_batch_size_per_device = 256
  - micro_batch_size_per_device_for_update = 4
  - micro_batch_size_per_device_for_experience = 16
```

## 二、职责边界（核心概念）

### 2.1 数据分配 vs 权重分配

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    数据分配 vs 权重分配（完全不同！）                          │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 【数据分配】- 谁处理哪些样本                                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Driver → Worker：  Ray RPC 切分（Driver 主动分配）                           │
│                     代码：batch.chunk(world_size)                           │
│                                                                             │
│  Worker → GPU：     DataLoader + DistributedSampler                         │
│                     每个 GPU 从数据集取自己的那部分                            │
│                                                                             │
│  micro_batch：      代码显式 split（Worker 内部）                            │
│                     data.split(micro_batch_size)                           │
│                                                                             │
│  ★ FSDP 不负责数据分配！                                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 【权重分配】- 模型参数存在哪里                                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  全局 FSDP（默认）：  跨所有 16 GPU 分片权重                                   │
│                      每个 GPU 存 1/16 权重                                   │
│                      All-Gather 跨机器                                      │
│                                                                             │
│  HSDP：              Worker 内部分片权重                                      │
│                      每个 GPU 存 1/8 权重                                    │
│                      All-Gather 只在单机内                                   │
│                                                                             │
│  ★ 只有 FSDP 负责权重分配！                                                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 各组件职责表

| 组件 | 数据分配 | 权重分配 | 通信 |
|------|----------|----------|------|
| **Driver** | 切分 batch 给 Worker | 无 | Ray RPC |
| **Ray RPC** | 传输数据切片 | 无 | 跨机器 |
| **DataLoader** | 分配数据给 GPU | 无 | 无 |
| **FSDP** | 无 | 分片权重、All-Gather、Reduce-Scatter | NCCL |
| **vLLM (TP)** | 无 | Tensor Parallel 分片 | NCCL |

## 四、数据分配详解

### 4.1 第一层：Driver → Worker（Ray RPC）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│              第一层：Driver → Worker 数据切分                                 │
│              负责人：Ray RPC (dispatch_dp_compute_data_proto)                │
└─────────────────────────────────────────────────────────────────────────────┘

Driver 端：
─────────────────────────────────────────────────────────────────────────────

  原始 batch:
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  batch_size = 512                                                       │
  │  shape: (512, seq_len)                                                  │
  │                                                                         │
  │  [sample_0, sample_1, ..., sample_511]                                  │
  └─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ dispatch_dp_compute_data_proto
                                    │ batch.chunk(world_size=2)
                                    │
                                    ▼
  切分后：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  batch_0: [sample_0, ..., sample_255]   → Worker 0                      │
  │  batch_1: [sample_256, ..., sample_511] → Worker 1                      │
  │                                                                         │
  │  每个 batch: (256, seq_len)                                             │
  └─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ Ray RPC 远程调用
                                    │ 数据通过共享内存传输
                                    │
                                    ▼
Worker 端：
─────────────────────────────────────────────────────────────────────────────

  Worker 0 收到 batch_0 (256条)
  Worker 1 收到 batch_1 (256条)


代码位置：
─────────────────────────────────────────────────────────────────────────────
```

### 4.2 第二层：Worker → GPU（DataLoader + DistributedSampler）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│              第二层：Worker → GPU 数据分配                                    │
│              负责人：DataLoader + DistributedSampler                         │
└─────────────────────────────────────────────────────────────────────────────┘

Worker 0 内部（收到 256 条数据）：
─────────────────────────────────────────────────────────────────────────────

  配置：
    - global_batch_size_per_device = 256  （每个设备处理的总量）
    - 8 个 GPU
  
  数据分配：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  DistributedSampler 自动分配：                                          │
  │                                                                         │
  │  GPU 0: 处理 sample_0, sample_8, sample_16, ...  (32条)                │
  │  GPU 1: 处理 sample_1, sample_9, sample_17, ...  (32条)                │
  │  GPU 2: 处理 sample_2, sample_10, sample_18, ... (32条)                │
  │  ...                                                                    │
  │  GPU 7: 处理 sample_7, sample_15, sample_23, ... (32条)                │
  │                                                                         │
  │  每个 GPU 处理 256 / 8 = 32 条数据                                       │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  注意：
    - 这是数据并行的标准做法
    - 每个 GPU 处理不同的样本
    - FSDP 不参与这个过程！


Worker 1 内部（收到 256 条数据）：
─────────────────────────────────────────────────────────────────────────────

  同样的分配方式：
    GPU 8:  32条
    GPU 9:  32条
    ...
    GPU 15: 32条
```

### 4.3 第三层：micro_batch 切分（代码显式 split）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│              第三层：micro_batch 切分                                         │
│              负责人：代码显式 split                                           │
└─────────────────────────────────────────────────────────────────────────────┘

为什么需要 micro_batch？
─────────────────────────────────────────────────────────────────────────────
  - 显存限制：一次放不下所有数据
  - 梯度累积：多个 micro_batch 累积后再更新


配置：
─────────────────────────────────────────────────────────────────────────────
  global_batch_size_per_device = 256      # 每个 GPU 处理的总数据量
  micro_batch_size_per_device_for_update = 4  # 每次 forward 的数据量
  
  每个 GPU 需要 256 / 4 = 64 个 micro_batch


Worker 0 内部，GPU 0 的数据流：
─────────────────────────────────────────────────────────────────────────────

  GPU 0 收到 32 条数据
       │
       │ 切分成 micro_batch
       │ 32 / 4 = 8 个 micro_batch
       ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  micro_batch_0: [sample_0]    (4条)                                     │
  │  micro_batch_1: [sample_8]    (4条)                                     │
  │  micro_batch_2: [sample_16]   (4条)                                     │
  │  ...                                                                    │
  │  micro_batch_7: [sample_56]   (4条)                                     │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ 循环处理每个 micro_batch
       ▼
  for micro_batch in micro_batches:
      forward(micro_batch)    # 前向
      backward(micro_batch)   # 后向
      累积梯度
       │
       ▼
  optimizer.step()  # 所有 micro_batch 处理完后更新


代码位置：
─────────────────────────────────────────────────────────────────────────────
  # verl/workers/actor/dp_actor.py:229-245
  def update_policy(self, data: DataProto):
      # 切分 mini_batch
      mini_batches = data.select(...).split(self.config.global_batch_size_per_device)
      
      for mini_batch in mini_batches:
          # 切分 micro_batch
          micro_batches = mini_batch.split(self.config.micro_batch_size_per_device_for_update)
          
          for micro_batch in micro_batches:
              # 前向后向
              log_probs = self._forward_micro_batch(micro_batch, temperature)
              loss = compute_policy_loss(...)
              loss.backward()
          
          # 梯度裁剪 + 优化器更新
          self._optimizer_step()
```

## 五、权重分配详解（FSDP）

### 5.1 FSDP 权重分片

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    FSDP 权重分片（默认全局 FSDP）                              │
│                    负责人：FSDP                                              │
└─────────────────────────────────────────────────────────────────────────────┘

权重存储：
─────────────────────────────────────────────────────────────────────────────

  7B 模型，权重总量 ≈ 14GB (bf16)

  全局 FSDP（fsdp_size = -1，默认）：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  GPU 0  (Worker 0): 权重分片 1/16  → 约 0.875GB                         │
  │  GPU 1  (Worker 0): 权重分片 2/16  → 约 0.875GB                         │
  │  ...                                                                    │
  │  GPU 7  (Worker 0): 权重分片 8/16  → 约 0.875GB                         │
  │  GPU 8  (Worker 1): 权重分片 9/16  → 约 0.875GB                         │
  │  ...                                                                    │
  │  GPU 15 (Worker 1): 权重分片 16/16 → 约 0.875GB                         │
  │                                                                         │
  │  每个 GPU 只存 1/16 权重，节省显存！                                      │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  HSDP（fsdp_size = 8）：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  Worker 0 内部（GPU 0-7）：每个 GPU 存 1/8 权重 → 约 1.75GB             │
  │  Worker 1 内部（GPU 8-15）：每个 GPU 存 1/8 权重 → 约 1.75GB            │
  │                                                                         │
  │  All-Gather 只在 Worker 内部，不跨机器                                   │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 FSDP 前向后向流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    FSDP 前向传播                                             │
└─────────────────────────────────────────────────────────────────────────────┘

每个 GPU 执行：

  Step 1: 本地只有权重分片
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  GPU 0: [shard_0] (1/16 权重)                                           │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ All-Gather（跨所有 16 GPU，包括跨机器）
       │
       ▼
  Step 2: 收集完整权重
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  GPU 0: [shard_0, shard_1, ..., shard_15] = 完整权重 (14GB)             │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ 前向计算
       │
       ▼
  Step 3: 计算输出
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  output = forward(完整权重, micro_batch)                                │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ 释放完整权重（只保留本地分片）
       │
       ▼
  Step 4: 释放显存
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  GPU 0: [shard_0] (回到只存分片状态)                                     │
  └─────────────────────────────────────────────────────────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│                    FSDP 后向传播                                             │
└─────────────────────────────────────────────────────────────────────────────┘

  Step 1: All-Gather 收集完整权重（同前向）
       │
       ▼
  Step 2: 后向计算梯度
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  grad = backward(完整权重, micro_batch)                                 │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ Reduce-Scatter（跨所有 16 GPU）
       │
       ▼
  Step 3: 同步梯度分片
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  GPU 0: [grad_shard_0] (只保留自己那部分权重的梯度)                       │
  └─────────────────────────────────────────────────────────────────────────┘
```

## 六、完整训练流程示例

### 6.1 Step 1: 生成阶段（Rollout / vLLM）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Step 1: 生成阶段                                          │
│                    使用 vLLM (Tensor Parallel)                               │
└─────────────────────────────────────────────────────────────────────────────┘

关键配置说明：
─────────────────────────────────────────────────────────────────────────────
  - rollout_batch_size = 128           # 最终需要多少个不同的"问题"
  - mini_rollout_batch_size = 32       # DataLoader 每次取多少个 prompt
  - rollout.n = 8                      # 每个 prompt 生成几个回答（GRPO需要 n>1）

  计算关系：
    - 循环次数 = rollout_batch_size / mini_rollout_batch_size = 128 / 32 = 4 轮
    - 每轮生成样本数 = mini_rollout_batch_size × n = 32 × 8 = 256 个样本
    - 最终样本数 = 128 × 8 = 1024 个样本

  为什么需要 mini_rollout_batch_size？
    - vLLM 需要 KV Cache 来生成
    - batch_size 越大，KV Cache 越大
    - 显存可能不够，所以分批生成


Driver 循环累积流程：
─────────────────────────────────────────────────────────────────────────────

  batch = None  # 初始化空 batch
  current_batch_size = 0  # 当前累积的"问题数"
  
  while current_batch_size < rollout_batch_size:  # 128 个问题
      
      # Step 1: 从 DataLoader 取 mini_batch (32 个 prompt)
      mini_batch = next(self.data_iterator)  # 32 个问题
      
      # Step 2: 为每个 prompt 生成 n 个回答
      # vLLM 内部会自动生成 n 个，并返回 32*n 个回答
      gen_batch_output = generate_sequences(mini_batch)  # 32*8=256 个样本
      
      # Step 3: repeat 对齐（代码中实现）
      # 将 prompt 重复 n 次，与回答对齐
      # [q1, q2, ..., q32] → [q1, q1, ..., q1, q2, q2, ..., q2, ...]
      
      # Step 4: 累积到总 batch
      batch = concat([batch, new_batch])
      current_batch_size += 32  # 累积的是"问题数"
  
  最终：128 个问题 × 8 个回答 = 1024 个样本


详细循环过程（4 轮）：
─────────────────────────────────────────────────────────────────────────────

  第 1 轮：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Driver: mini_batch (32 prompts)                                        │
  │       │                                                                  │
  │       │ Ray RPC 切分: 32 → 16 + 16                                       │
  │       ▼                                                                  │
  │  Worker 0: 16 prompts                                                   │
  │  Worker 1: 16 prompts                                                   │
  │       │                                                                  │
  │       │ vLLM 生成（n=8，每个 prompt 生成 8 个回答）                        │
  │       ▼                                                                  │
  │  Worker 0: 16×8 = 128 samples                                           │
  │  Worker 1: 16×8 = 128 samples                                           │
  │       │                                                                  │
  │       ◄─────────────────────────────────────────────────────────────────│
  │       │                                                                  │
  │       ▼ concat + repeat 对齐                                             │
  │  batch = 32×8 = 256 samples                                             │
  │  current_batch_size = 32 个问题                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  第 2 轮：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  batch = 64×8 = 512 samples                                             │
  │  current_batch_size = 64 个问题                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  第 3 轮：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  batch = 96×8 = 768 samples                                             │
  │  current_batch_size = 96 个问题                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  第 4 轮：
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  batch = 128×8 = 1024 samples ✓                                         │
  │  current_batch_size = 128 >= rollout_batch_size                         │
  │                                                                         │
  │  循环结束，返回完整 batch                                                 │
  └─────────────────────────────────────────────────────────────────────────┘


Worker 内部（每轮处理）：
─────────────────────────────────────────────────────────────────────────────

  收到 16 prompts（mini_rollout_batch_size / world_size）
       │
       │ vLLM Tensor Parallel (TP=2)
       │ 8 GPU 分成 4 组，每组 2 GPU 做 TP
       ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  TP 组 0: GPU 0,1  → 处理 4 prompts  → 生成 4×8=32 samples               │
  │  TP 组 1: GPU 2,3  → 处理 4 prompts  → 生成 4×8=32 samples               │
  │  TP 组 2: GPU 4,5  → 处理 4 prompts  → 生成 4×8=32 samples               │
  │  TP 组 3: GPU 6,7  → 处理 4 prompts  → 生成 4×8=32 samples               │
  │                                                                         │
  │  每个 TP 组内：权重按列切分，并行计算                                      │
  │  vLLM 的 n 参数自动生成多个回答                                           │
  └─────────────────────────────────────────────────────────────────────────┘
       │
       │ vLLM 生成 16×8 = 128 samples
       ▼
  Ray RPC 返回 Driver


Driver 最终收集：
─────────────────────────────────────────────────────────────────────────────
  经过 4 轮循环累积：
    - 问题数：128 个
    - 样本数：128 × 8 = 1024 个
  
  每个问题有 8 个回答，用于 GRPO 组内比较

      while True:
          # Step 1: 从 DataLoader 取 mini_batch
          batch_dict = next(self.data_iterator)
          new_batch = DataProto.from_single_dict(batch_dict, ...)
          
          # Step 2: 为每个样本生成唯一 uid（用于 GRPO 分组）
          new_batch.non_tensor_batch["uid"] = [uuid.uuid4() for _ in range(len(new_batch))]
          
          # Step 3: 生成回答（vLLM 内部处理 n 个）
          gen_batch_output = self.actor_rollout_ref_wg.generate_sequences(gen_batch)
          
          # Step 4: repeat 对齐（prompt 重复 n 次）
          new_batch = new_batch.repeat(repeat_times=n, interleave=True)
          new_batch = new_batch.union(gen_batch_output)
          
          # Step 5: 累积
          batch = DataProto.concat([batch, new_batch])
          current_batch_size = len(batch) // n  # 计算问题数
          
          # Step 6: 检查是否达到目标
          if current_batch_size >= rollout_batch_size:
              return batch
```

### 7.1 TP vs FSDP

```

└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────────────────┤
│  用途：训练                                                                 │

│  数据：所有 GPU 处理相同数据                                                 │
│  通信：All-Reduce 同步中间结果                                               │
│  场景：加速推理，降低延迟                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 十一、mini_batch vs micro_batch 对比

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    mini_batch vs micro_batch vs rollout.n 对比              │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  生成阶段（vLLM 推理）                                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  配置参数：                                                                  │
│    - rollout_batch_size: 最终需要多少个"问题"（如 128）                       │
│    - mini_rollout_batch_size: DataLoader 每次取多少个 prompt（如 32）        │
│    - rollout.n: 每个 prompt 生成几个回答（如 8，GRPO 需要 n>1）               │
│                                                                             │
│  计算关系：                                                                  │
│    - 循环次数 = rollout_batch_size / mini_rollout_batch_size                │
│    - 每轮生成样本数 = mini_rollout_batch_size × n                            │
│    - 最终样本数 = rollout_batch_size × n                                    │
│                                                                             │
│  流程：                                                                      │
│    while current_questions < rollout_batch_size:                            │
│        mini_batch = next(dataloader)  # 取 32 个 prompt                     │
│        responses = vllm.generate(mini_batch, n=8)  # 生成 32×8=256 个回答   │
│        # repeat: 将每个 prompt 重复 n 次，与回答对齐                          │
│        batch.concat(responses)                                              │
│        current_questions += 32                                              │
│                                                                             │
│  目的：                                                                      │
│    - mini_rollout_batch_size 控制 vLLM KV Cache 显存                         │
│    - batch 太大会 OOM                                                        │
│    - rollout.n 控制每个问题的回答数，用于 GRPO 组内比较                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  训练阶段（FSDP 训练）                                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  配置参数：                                                                  │
│    - global_batch_size_per_device: 每个 GPU 处理的总数据量                   │
│    - micro_batch_size_per_device_for_update: 每次 forward 的数据量          │
│                                                                             │
│  流程：                                                                      │
│    for mini_batch in data.split(global_batch_size):                         │
│        for micro_batch in mini_batch.split(micro_batch_size):               │
│            forward(micro_batch)                                             │
│            backward(micro_batch)                                            │
│        optimizer.step()  # 梯度累积后更新                                    │
│                                                                             │
│  目的：                                                                      │
│    - 控制训练显存（forward/backward 的激活值）                               │
│    - 梯度累积：多个 micro_batch 累积后更新                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  关键区别                                                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  生成阶段：                                                                  │
│    - mini_rollout_batch_size 控制每次 vLLM 处理的 prompt 数                  │
│    - rollout.n 控制每个 prompt 生成几个回答                                  │
│    - 循环累积"问题数"，不是"样本数"                                          │
│    - 显存主要消耗在 KV Cache                                                 │
│                                                                             │
│  训练阶段：                                                                  │
│    - micro_batch_size 控制 每次 forward/backward 的数据量                    │
│    - 有梯度累积（多个 micro_batch 累积后更新）                                │
│    - 显存主要消耗在激活值和梯度                                               │
│                                                                             │
│  样本数计算：                                                                │
│    - 生成阶段输出样本数 = rollout_batch_size × rollout.n                     │
│    - 训练阶段处理样本数 = 同上（同一个 batch）                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  具体例子（本文档配置）                                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  生成阶段：                                                                  │
│    - rollout_batch_size = 128（最终需要128个问题）                           │
```
