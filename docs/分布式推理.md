# EasyR1 分布式推理详解

> 本文档详解 EasyR1 中 vLLM 推理的分布式策略，以及 FSDP 训练权重如何同步到 vLLM 推理引擎。

---

## 一、为什么训练和推理用不同的并行方式？

### 1.1 核心差异

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    训练 vs 推理 的不同需求                                │
└─────────────────────────────────────────────────────────────────────────┘

训练 (FSDP):
  - 需求: 节省显存，支持大模型训练
  - 特点: 每层动态 All-Gather 收集权重，计算后释放
  - 延迟: 高 (每层都要通信)
  - 适用: 不在乎延迟，在乎显存

推理 (Tensor Parallel):
  - 需求: 低延迟，高吞吐
  - 特点: 权重永久切分，每层并行计算
  - 延迟: 低 (无需动态收集权重)
  - 适用: 在乎延迟，不在乎权重存储方式
```

### 1.2 为什么 FSDP 不适合推理？

```
假设生成 512 个 token，模型 32 层

FSDP 推理 (假设用):
───────────────────────────────────────────────────────────────────────────
每个 token 的每层都要:
  All-Gather (收集权重) → 计算 → 释放

总通信次数: 512 tokens × 32 层 × 2 (gather + 释放) = 32,768 次通信
延迟: 非常高！

Tensor Parallel 推理 (vLLM):
───────────────────────────────────────────────────────────────────────────
权重已经切分好，每个 token 的每层:
  并行计算 → All-Reduce (结果同步)

总通信次数: 512 tokens × 32 层 × 1 = 16,384 次通信
延迟: 比 FSDP 低 50%+
```

## 三、具体例子：8 卡训练 + 推理

### 3.1 配置

```yaml
# 假设配置
trainer:
  n_gpus_per_node: 8    # 8 个 GPU

worker:
  rollout:
    tensor_parallel_size: 2  # vLLM 用 TP=2
```

### 3.2 GPU 分组 (Device Mesh)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Device Mesh                                     │
│                    mesh_shape = (4, 2)                                  │
│                    dim_names = ("dp", "tp")                             │
└─────────────────────────────────────────────────────────────────────────┘

           dp=0                dp=1                dp=2                dp=3
        ┌─────────┐        ┌─────────┐        ┌─────────┐        ┌─────────┐
  tp=0  │  GPU 0  │        │  GPU 2  │        │  GPU 4  │        │  GPU 6  │
        ├─────────┤        ├─────────┤        ├─────────┤        ├─────────┤
  tp=1  │  GPU 1  │        │  GPU 3  │        │  GPU 5  │        │  GPU 7  │
        └─────────┘        └─────────┘        └─────────┘        └─────────┘

含义：
- dp 维度：数据并行，4 组处理不同数据
- tp 维度：Tensor Parallel，每组内 2 卡切分模型权重
```

### 3.3 代码实现

```python
# verl/workers/fsdp_workers.py:381-405
def _build_rollout(self):
    tp_size = self.config.rollout.tensor_parallel_size  # TP=2
    dp_size = self.world_size // tp_size  # dp_size = 8 / 2 = 4
    
    # 创建 (dp, tp) 设备网格
    rollout_device_mesh = init_device_mesh(
        "cuda", 
        mesh_shape=(dp_size, tp_size),  # (4, 2)
        mesh_dim_names=("dp", "tp")
    )
    
    # 创建 vLLM 推理引擎
    self.rollout = vLLMRollout(
        tensor_parallel_size=tp_size,  # TP=2
        ...
    )
    
    # 创建 FSDP-vLLM 分片管理器
    self.rollout_sharding_manager = FSDPVLLMShardingManager(
        module=self.fsdp_module,        # FSDP Actor
        inference_engine=self.rollout,  # vLLM 引擎
        device_mesh=rollout_device_mesh,
    )
```

## 四、完整流程详解

### Phase 1: 初始化

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Step 1: 创建 FSDP Actor (训练用)                                        │
└─────────────────────────────────────────────────────────────────────────┘

每个 GPU 存 1/8 的 Actor 权重：

GPU 0: W_shard_0    GPU 1: W_shard_1    GPU 2: W_shard_2    GPU 3: W_shard_3
GPU 4: W_shard_4    GPU 5: W_shard_5    GPU 6: W_shard_6    GPU 7: W_shard_7


┌─────────────────────────────────────────────────────────────────────────┐
│  Step 2: 创建 vLLM 推理引擎 (推理用)                                      │
└─────────────────────────────────────────────────────────────────────────┘

vLLM 按 TP=2 初始化，每组 2 卡共享权重：

           dp=0                dp=1                dp=2                dp=3
        ┌─────────┐        ┌─────────┐        ┌─────────┐        ┌─────────┐
  tp=0  │  GPU 0  │        │  GPU 2  │        │  GPU 4  │        │  GPU 6  │
        │ W_left  │        │ W_left  │        │ W_left  │        │ W_left  │
        ├─────────┤        ├─────────┤        ├─────────┤        ├─────────┤
  tp=1  │  GPU 1  │        │  GPU 3  │        │  GPU 5  │        │  GPU 7  │
        │ W_right │        │ W_right │        │ W_right │        │ W_right │
        └─────────┘        └─────────┘        └─────────┘        └─────────┘

注意：此时 vLLM 的权重是随机初始化的，还没从 FSDP 同步！
```

### Phase 2: 同步权重 (FSDP → vLLM)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Step 3: 从 FSDP 收集完整权重                                             │
└─────────────────────────────────────────────────────────────────────────┘

代码:
  actor_weights = get_model_state_dict(self.module)
  # verl/workers/sharding_manager/fsdp_vllm.py:140

每个 GPU 都参与 All-Gather：

GPU 0 广播 W_shard_0 ──► 所有 GPU 收到
GPU 1 广播 W_shard_1 ──► 所有 GPU 收到
GPU 2 广播 W_shard_2 ──► 所有 GPU 收到
...
GPU 7 广播 W_shard_7 ──► 所有 GPU 收到

结果：每个 GPU 都有完整权重 W = [W_shard_0, W_shard_1, ..., W_shard_7]


┌─────────────────────────────────────────────────────────────────────────┐
│  Step 4: 按 TP 方式切分权重，加载到 vLLM                                   │
└─────────────────────────────────────────────────────────────────────────┘

代码:
  model.load_weights(self._make_weight_iterator(actor_weights))
  # verl/workers/sharding_manager/fsdp_vllm.py:147

vLLM 内部按 TP=2 切分权重：

对于每个 Linear 层 W (假设 shape=[4096, 4096])：

           dp=0 (GPU 0,1)      dp=1 (GPU 2,3)      dp=2 (GPU 4,5)      dp=3 (GPU 6,7)
        ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  tp=0  │ W[:, :2048]  │    │ W[:, :2048]  │    │ W[:, :2048]  │    │ W[:, :2048]  │
        │ (左半边)     │    │ (左半边)     │    │ (左半边)     │    │ (左半边)     │
        ├──────────────┤    ├──────────────┤    ├──────────────┤    ├──────────────┤
  tp=1  │ W[:, 2048:]  │    │ W[:, 2048:]  │    │ W[:, 2048:]  │    │ W[:, 2048:]  │
        │ (右半边)     │    │ (右半边)     │    │ (右半边)     │    │ (右半边)     │
        └──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘

关键点：
- dp 维度：每组存完整权重（用于处理不同数据）
- tp 维度：组内两卡各存一半权重（用于并行计算）
```

### Phase 3: vLLM 生成

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Step 5: 数据分发                                                        │
└─────────────────────────────────────────────────────────────────────────┘

假设 batch_size = 128，分成 4 份给 4 个 dp 组：

dp=0 (GPU 0,1): 处理 batch_0 (32 样本)
dp=1 (GPU 2,3): 处理 batch_1 (32 样本)
dp=2 (GPU 4,5): 处理 batch_2 (32 样本)
dp=3 (GPU 6,7): 处理 batch_3 (32 样本)


┌─────────────────────────────────────────────────────────────────────────┐
│  Step 6: TP 组内 All-Gather 数据                                         │
└─────────────────────────────────────────────────────────────────────────┘

代码:
  all_gather_data_proto(data, size=self.tp_size, group=self.tp_group)
  # verl/workers/sharding_manager/fsdp_vllm.py:219

每组内的 2 卡都拿到相同数据：

dp=0 组:
  GPU 0 收到 batch_0
  GPU 1 收到 batch_0  ← 同一组的数据相同！


┌─────────────────────────────────────────────────────────────────────────┐
│  Step 7: vLLM Tensor Parallel 推理                                       │
└─────────────────────────────────────────────────────────────────────────┘

以 dp=0 组 (GPU 0, 1) 为例，处理 batch_0：

对于每个 Linear 层 y = x @ W：

GPU 0 (tp=0):                    GPU 1 (tp=1):
  输入: x (32, 4096)               输入: x (32, 4096)  ← 相同输入
  权重: W_left [4096, 2048]        权重: W_right [4096, 2048]
  
  计算: y_left = x @ W_left        计算: y_right = x @ W_right
  输出: (32, 2048)                 输出: (32, 2048)

然后 All-Reduce (拼接或求和，取决于层类型):

  y = concat([y_left, y_right]) = (32, 4096)
  
  GPU 0 和 GPU 1 都得到完整输出 y


┌─────────────────────────────────────────────────────────────────────────┐
│  Step 8: TP 组内取回自己的数据                                             │
└─────────────────────────────────────────────────────────────────────────┘

代码:
  data = data.chunk(chunks=self.tp_size)[self.tp_rank]
  # verl/workers/sharding_manager/fsdp_vllm.py:225

dp=0 组:
  GPU 0 (tp_rank=0): 取 chunk[0]
  GPU 1 (tp_rank=1): 取 chunk[1]

因为 tp_size=2 时数据是复制的，所以两卡结果相同。
```

## 六、Tensor Parallel 详解

### 6.1 列切分

```
对于 Linear 层: y = x @ W

W shape: [in_features, out_features] = [4096, 4096]

TP=2 列切分:
───────────────────────────────────────────────────────────────────────────

GPU 0: W_left  = W[:, :2048]     shape: [4096, 2048]
GPU 1: W_right = W[:, 2048:]     shape: [4096, 2048]

计算:
  GPU 0: y_left  = x @ W_left     shape: [batch, 2048]
  GPU 1: y_right = x @ W_right    shape: [batch, 2048]

拼接:
  y = concat([y_left, y_right], dim=-1)  shape: [batch, 4096]

数学等价:
  y = x @ [W_left, W_right] = x @ W  ✓
```

### 6.2 行切分

```
对于下一个 Linear 层: z = y @ V

V shape: [4096, 4096]

TP=2 行切分:
───────────────────────────────────────────────────────────────────────────

GPU 0: V_top    = V[:2048, :]    shape: [2048, 4096]
GPU 1: V_bottom = V[2048:, :]    shape: [2048, 4096]

计算 (注意 y 已经是分开的):
  GPU 0: z_0 = y_left @ V_top      shape: [batch, 4096]
  GPU 1: z_1 = y_right @ V_bottom  shape: [batch, 4096]

All-Reduce Sum:
  z = z_0 + z_1  shape: [batch, 4096]

数学等价:
  z = y_left @ V_top + y_right @ V_bottom
    = [y_left, y_right] @ [V_top; V_bottom]
    = y @ V  ✓
```

### 6.3 MLP 层的 TP

```
MLP: output = GELU(x @ W1) @ W2

W1: [4096, 16384]  (扩展层)
W2: [16384, 4096]  (投影层)

TP=2:
───────────────────────────────────────────────────────────────────────────

W1 列切分:
  GPU 0: W1_left  = W1[:, :8192]    [4096, 8192]
  GPU 1: W1_right = W1[:, 8192:]    [4096, 8192]

W2 行切分 (配合 W1):
  GPU 0: W2_top    = W2[:8192, :]   [8192, 4096]
  GPU 1: W2_bottom = W2[8192:, :]   [8192, 4096]

计算:
  GPU 0: h_0 = GELU(x @ W1_left) @ W2_top      [batch, 4096]
  GPU 1: h_1 = GELU(x @ W1_right) @ W2_bottom  [batch, 4096]

All-Reduce Sum:
  output = h_0 + h_1

通信: 只需一次 All-Reduce (在最后)
```

## 八、总结对比

| 阶段 | 使用方式 | 权重状态 | 数据分配 | 通信 |
|-----|---------|---------|---------|------|
| **初始化** | FSDP | 分片存储 (1/8) | - | - |
| **同步到 vLLM** | FSDP → vLLM | All-Gather 收集完整，再按 TP 切分 | - | All-Gather |
| **Rollout** | vLLM TP | 永久切分 (TP=2) | dp 维度不同，tp 维度相同 | All-Reduce |
| **训练** | FSDP | 动态收集/释放 | 每卡不同 | All-Gather + Reduce-Scatter |

## 九、常见问题

### Q1: 为什么每次 Rollout 都要同步权重？

因为训练会更新 Actor 的权重，vLLM 需要最新的权重才能生成高质量的 response。

### Q2: 为什么不直接用 FSDP 做推理？

FSDP 每层都要 All-Gather 收集权重，延迟太高。Tensor Parallel 权重已切分好，计算更高效。

### Q3: TP 组内为什么要 All-Gather 数据？

因为 TP 组内的每个 GPU 只存一半权重，但计算需要完整输入，所以先复制数据到每个 GPU。

### Q4: dp 和 tp 的区别？

- **dp (数据并行)**: 不同组处理不同数据
- **tp (Tensor Parallel)**: 同组内切分权重并行计算
