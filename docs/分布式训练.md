# EasyR1 分布式训练详解

> 本文档从分布式角度解释 EasyR1 的并行策略，解答"样本分卡 + 权重分片"如何协同工作。

---

## 一、先理解三种并行方式

### 1.1 数据并行 (Data Parallel, DP)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         数据并行 (DP)                                    │
│                    每卡完整模型，每卡不同数据                              │
└─────────────────────────────────────────────────────────────────────────┘

GPU 0                    GPU 1                    GPU 2                    GPU 3
┌──────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ 模型 (完整)   │        │ 模型 (完整)   │        │ 模型 (完整)   │        │ 模型 (完整)   │
│              │        │              │        │              │        │              │
│ 数据 batch_0 │        │ 数据 batch_1 │        │ 数据 batch_2 │        │ 数据 batch_3 │
└──────────────┘        └──────────────┘        └──────────────┘        └──────────────┘
        │                       │                       │                       │
        ▼                       ▼                       ▼                       ▼
    算 loss_0               算 loss_1               算 loss_2               算 loss_3
        │                       │                       │                       │
        └───────────────────────┴───────────────────────┴───────────────────────┘
                                        │
                              All-Reduce (梯度同步)
                                        │
                                        ▼
                            每卡得到相同的梯度
                                        │
                                        ▼
                            每卡独立更新参数 (结果相同)
```

**特点**：
- 每卡存**完整模型** (显存浪费)
- 每卡处理**不同数据**
- 反向传播后 **All-Reduce 同步梯度**
- 本质：加速训练，但不节省显存

---

### 1.2 模型并行 (Model Parallel, MP)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         模型并行 (MP)                                    │
│                    每卡部分模型，每卡相同数据                              │
└─────────────────────────────────────────────────────────────────────────┘

GPU 0                    GPU 1                    GPU 2                    GPU 3
┌──────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ Layer 0-3    │        │ Layer 4-7    │        │ Layer 8-11   │        │ Layer 12-15  │
│ (1/4 模型)   │        │ (1/4 模型)   │        │ (1/4 模型)   │        │ (1/4 模型)   │
│              │        │              │        │              │        │              │
│ 数据 batch   │        │ 数据 batch   │        │ 数据 batch   │        │ 数据 batch   │
└──────────────┘        └──────────────┘        └──────────────┘        └──────────────┘
        │                       │                       │                       │
        ▼                       │                       │                       │
    计算 L0-3                   │                       │                       │
        │                       │                       │                       │
        └─────── Send ─────────►│                       │                       │
                                ▼                       │                       │
                            计算 L4-7                   │                       │
                                │                       │                       │
                                └─────── Send ─────────►│                       │
                                                        ▼                       │
                                                    计算 L8-11                  │
                                                        │                       │
                                                        └─────── Send ─────────►│
                                                                                ▼
                                                                            计算 L12-15
```

**特点**：
- 每卡只存**部分模型** (节省显存)
- 每卡处理**相同数据**
- 层间需要 **Send/Recv 传递激活值**
- 本质：训练大模型，但有通信开销

---

### 1.3 FSDP (Fully Sharded Data Parallel)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                            FSDP                                         │
│              静态：每卡部分权重    计算：临时收集完整权重                   │
│              每卡不同数据          本质是"显存优化的数据并行"              │
└─────────────────────────────────────────────────────────────────────────┘
```

**这是 EasyR1 训练时使用的主要方式！**

## 二、FSDP 详解：回答你的疑问

### 2.1 你的疑问

> "如果权重也分开存，但每张卡样本不一样，这不是会出问题吗？"

**答案**：不会！因为 FSDP 在**计算时临时收集完整权重**，计算完就释放。

### 2.2 FSDP 工作流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    FSDP 静态存储 (不计算时)                              │
└─────────────────────────────────────────────────────────────────────────┘

GPU 0                    GPU 1                    GPU 2                    GPU 3
┌──────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ W_shard_0    │        │ W_shard_1    │        │ W_shard_2    │        │ W_shard_3    │
│ (1/4 权重)   │        │ (1/4 权重)   │        │ (1/4 权重)   │        │ (1/4 权重)   │
│              │        │              │        │              │        │              │
│ 数据 batch_0 │        │ 数据 batch_1 │        │ 数据 batch_2 │        │ 数据 batch_3 │
└──────────────┘        └──────────────┘        └──────────────┘        └──────────────┘

注意：每卡只有 1/4 权重，但有不同的数据！


┌─────────────────────────────────────────────────────────────────────────┐
│                    FSDP 前向传播 (计算某一层时)                          │
└─────────────────────────────────────────────────────────────────────────┘

Step 1: All-Gather (收集完整权重)
───────────────────────────────────────────────────────────────────────────
GPU 0 广播 W_shard_0 ──► 所有卡都收到
GPU 1 广播 W_shard_1 ──► 所有卡都收到
GPU 2 广播 W_shard_2 ──► 所有卡都收到
GPU 3 广播 W_shard_3 ──► 所有卡都收到

此时每卡都临时拥有完整权重 W = [W_shard_0, W_shard_1, W_shard_2, W_shard_3]

GPU 0                    GPU 1                    GPU 2                    GPU 3
┌──────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ W (完整)     │        │ W (完整)     │        │ W (完整)     │        │ W (完整)     │
│ 数据 batch_0 │        │ 数据 batch_1 │        │ 数据 batch_2 │        │ 数据 batch_3 │
└──────────────┘        └──────────────┘        └──────────────┘        └──────────────┘

Step 2: 本地计算
───────────────────────────────────────────────────────────────────────────
每卡用完整权重 + 自己的数据计算：

GPU 0: output_0 = forward(batch_0, W)
GPU 1: output_1 = forward(batch_1, W)
GPU 2: output_2 = forward(batch_2, W)
GPU 3: output_3 = forward(batch_3, W)

Step 3: 释放非本卡权重
───────────────────────────────────────────────────────────────────────────
计算完立即释放，只保留自己的 shard：

GPU 0                    GPU 1                    GPU 2                    GPU 3
┌──────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ W_shard_0    │        │ W_shard_1    │        │ W_shard_2    │        │ W_shard_3    │
│ output_0     │        │ output_1     │        │ output_2     │        │ output_3     │
└──────────────┘        └──────────────┘        └──────────────┘        └──────────────┘


┌─────────────────────────────────────────────────────────────────────────┐
│                    FSDP 反向传播 (计算梯度时)                            │
└─────────────────────────────────────────────────────────────────────────┘

Step 1: All-Gather (同前向，收集完整权重)

Step 2: 计算梯度
───────────────────────────────────────────────────────────────────────────
GPU 0: grad_0 = backward(batch_0, W)    # 完整权重的梯度
GPU 1: grad_1 = backward(batch_1, W)
GPU 2: grad_2 = backward(batch_2, W)
GPU 3: grad_3 = backward(batch_3, W)

Step 3: Reduce-Scatter (梯度分片归约)
───────────────────────────────────────────────────────────────────────────
把梯度按 shard 切分，每个 GPU 收集对应 shard 的梯度求和：

GPU 0 收集所有卡的 grad_shard_0 并求和: grad_shard_0 = grad_0[0] + grad_1[0] + grad_2[0] + grad_3[0]
GPU 1 收集所有卡的 grad_shard_1 并求和: grad_shard_1 = grad_0[1] + grad_1[1] + grad_2[1] + grad_3[1]
GPU 2 收集所有卡的 grad_shard_2 并求和: grad_shard_2 = grad_0[2] + grad_1[2] + grad_2[2] + grad_3[2]
GPU 3 收集所有卡的 grad_shard_3 并求和: grad_shard_3 = grad_0[3] + grad_1[3] + grad_2[3] + grad_3[3]

这就是正确的梯度！因为：
  total_grad = grad_0 + grad_1 + grad_2 + grad_3  (所有数据的梯度)
  total_grad_shard_i = total_grad[i]  (按分片取)
```

### 2.3 为什么正确？

```
数学证明：

假设有 4 个 batch: batch_0, batch_1, batch_2, batch_3
总损失: L = L(batch_0) + L(batch_1) + L(batch_2) + L(batch_3)
总梯度: ∂L/∂W = ∂L(batch_0)/∂W + ∂L(batch_1)/∂W + ∂L(batch_2)/∂W + ∂L(batch_3)/∂W

FSDP 做的事情：
1. 每卡用完整 W 计算自己 batch 的梯度
2. Reduce-Scatter 把梯度按 shard 归约

结果：
  GPU 0 得到: ∂L/∂W_shard_0 = ∂L(batch_0)/∂W_shard_0 + ... + ∂L(batch_3)/∂W_shard_0
  GPU 1 得到: ∂L/∂W_shard_1 = ∂L(batch_0)/∂W_shard_1 + ... + ∂L(batch_3)/∂W_shard_1
  ...

这正是我们想要的！
```

## 四、Micro Batch：解决显存不足

### 4.1 问题

即使 FSDP 分片了权重，单卡显存可能还是不够放下一个 batch 的激活值。

### 4.2 解决方案：梯度累积

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Micro Batch                                      │
│              把一个 batch 拆成多个 micro-batch，逐步计算                    │
└─────────────────────────────────────────────────────────────────────────┘

假设 global_batch_size = 128, 8 卡, micro_batch_size = 4

每卡分到的数据: 128 / 8 = 16 样本
每卡 micro-batch 数: 16 / 4 = 4 次

GPU 0 的计算流程:
───────────────────────────────────────────────────────────────────────────
micro_batch_0: [样本 0-3]   → forward → backward → 累积梯度
micro_batch_1: [样本 4-7]   → forward → backward → 累积梯度
micro_batch_2: [样本 8-11]  → forward → backward → 累积梯度
micro_batch_3: [样本 12-15] → forward → backward → 累积梯度
───────────────────────────────────────────────────────────────────────────
然后 Reduce-Scatter 同步梯度
然后优化器更新
```

### 4.3 代码配置

```yaml
# examples/config.yaml
worker:
  actor:
    global_batch_size: 128  # 全局 batch 大小
    micro_batch_size_per_device_for_update: 1  # 每卡每次更新的 micro-batch
    # 每卡梯度累积步数 = 128 / 8卡 / 1 = 16 步
```

## 六、训练流程中的分布式通信

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    GRPO 训练一轮的通信过程                                │
└─────────────────────────────────────────────────────────────────────────┘

Step 1: 数据分发 (Driver → Workers)
───────────────────────────────────────────────────────────────────────────
Driver 把 batch 数据分片发送给每个 Worker
每 Worker 收到不同的数据 (数据并行)

Step 2: Rollout 生成 (Workers 内部)
───────────────────────────────────────────────────────────────────────────
每个 Worker:
  - 加载权重到 vLLM (从 FSDP 模块同步)
  - vLLM 用 Tensor Parallel 生成回答
  - 通信: All-Gather (TP 组内)

Step 3: 计算奖励 (Workers 独立)
───────────────────────────────────────────────────────────────────────────
每个 Worker 独立计算自己数据的奖励
无通信

Step 4: 计算 old_log_probs (Workers 内部)
───────────────────────────────────────────────────────────────────────────
每个 Worker:
  - FSDP All-Gather 收集 Actor 权重
  - 前向计算 log_probs
  - 释放权重
  - 通信: All-Gather (FSDP 组内)

Step 5: GRPO 组内标准化 (Driver)
───────────────────────────────────────────────────────────────────────────
所有 Workers 把数据发回 Driver
Driver 统一计算 advantages (组内归一化)
Driver 把带 advantages 的数据发回 Workers
  - 通信: Gather + Scatter

Step 6: 更新 Actor (Workers 内部)
───────────────────────────────────────────────────────────────────────────
每个 Worker:
  - FSDP All-Gather 收集权重
  - 前向 + 反向计算
  - FSDP Reduce-Scatter 同步梯度
  - 优化器更新
  - 通信: All-Gather + Reduce-Scatter (FSDP 组内)
```

## 七、总结对比

| 方式 | 权重存储 | 数据分配 | 通信时机 | 通信类型 | 目的 |
|-----|---------|---------|---------|---------|------|
| **DP** | 每卡完整 | 每卡不同 | 反向后 | All-Reduce | 加速训练 |
| **MP** | 每卡部分 | 每卡相同 | 层间 | Send/Recv | 训练大模型 |
| **FSDP** | 每卡 1/N | 每卡不同 | 每层前后 | All-Gather + Reduce-Scatter | 节省显存 |
| **TP** | 每卡 1/N | 每卡相同 | 每层 | All-Reduce | 推理低延迟 |

## 八、回答你的问题

### Q1: "样本分卡计算 + micro batch 计算，这算不算分布式？"

**算！** 这是**数据并行**的核心思想：
- 样本分卡 = 数据并行
- micro batch = 梯度累积（解决显存不足）
- 本质：多卡并行处理不同数据，加速训练

### Q2: "权重分开存，每张卡样本不一样，不会出问题吗？"

**不会！** 关键在于 FSDP 的工作方式：
1. **静态存储**：每卡只存 1/N 权重（节省显存）
2. **计算时**：All-Gather 临时收集完整权重
3. **计算**：用完整权重 + 自己的数据计算
4. **反向后**：Reduce-Scatter 把梯度分片归约
5. **释放**：丢弃非本卡权重

**数学上完全正确**，等价于：
```
总梯度 = Σ(每卡用完整权重计算的梯度)
      = Reduce-Scatter 后每卡得到的梯度分片之和
```

### Q3: "那这和普通数据并行有什么区别？"

| | 普通 DP | FSDP |
|--|--------|------|
| 显存占用 | 每卡完整模型 | 每卡 1/N 模型 |
| 通信量 | 1×梯度 | 2×权重 + 1×梯度 |
| 适用场景 | 小模型 | 大模型 |

FSDP 本质是**显存优化的数据并行**，用更多通信换更少显存。
