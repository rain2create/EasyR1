# EasyR1 Worker 架构详解

> 本文档解释 Worker、三合一架构、以及与分布式的关系。

---

## 一、核心概念

### 1.1 Worker 是什么？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          Worker 的定义                                   │
└─────────────────────────────────────────────────────────────────────────┘

Worker 不是"一张卡"，而是一个"进程"，管理一组 GPU！  可以理解为一台机器就是一个worker 这里是一台机器(8张gpu)

一个 Worker:
  - 是一个 Ray Actor（分布式进程）
  - 管理一组 GPU（比如 8 卡）
  - 包含多个模型组件（Actor、Rollout、Ref）
  - 内部通过 FSDP/TP 做分布式计算
```

woker的存在主要是为了Ray分布式调度(跨机器！！！通信，多台机器同时启动进程) 以及 方便显存管理 （传统要存三个模型，有了worker之后可只存俩个，省显存）！！！
传统三个模型分三台机器的话 就无法同时训练 无法同时启动进程


### 1.2 三合一是什么？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ActorRolloutRef 三合一架构                            │
└─────────────────────────────────────────────────────────────────────────┘

一个 Worker 内部包含三个组件：

┌─────────────────────────────────────────────────────────────────────────┐
│                           FSDPWorker                                    │
│                     (一个进程，管理 8 个 GPU)                             │
│                                                                         │
│   ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐        │
│   │     Actor       │  │    Rollout      │  │   Ref Policy    │        │
│   │   (FSDP 训练)   │  │  (vLLM 推理)    │  │  (FSDP 参考)    │        │
│   │                 │  │                 │  │                 │        │
│   │ - 权重分片存储   │  │ - Tensor Paral │  │ - 权重分片存储   │        │
│   │ - 计算梯度      │  │ - 生成 response │  │ - 计算 KL 散度  │        │
│   │ - 参数更新      │  │                 │  │                 │        │
│   └─────────────────┘  └─────────────────┘  └─────────────────┘        │
│                                                                         │
│   共享同一组 GPU (8 卡)，通过显存复用节省资源                              │
└─────────────────────────────────────────────────────────────────────────┘
```

## 三、分布式架构详解

### 3.1 单机 8 卡场景

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    单机 8 卡，1 个 Worker                                │
└─────────────────────────────────────────────────────────────────────────┘

                    ┌─────────────────────────────────────┐
                    │         Driver (Ray 主进程)          │
                    │   - 数据分发                         │
                    │   - GRPO 组内标准化                  │
                    │   - 收集指标                         │
                    └─────────────────────────────────────┘
                                     │
                                     │ RPC 调用
                                     ▼
        ┌─────────────────────────────────────────────────────────────┐
        │                    FSDPWorker (1 个进程)                     │
        │                                                             │
        │  GPU 0      GPU 1      GPU 2      GPU 3      ...   GPU 7   │
        │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐        ┌──────┐   │
        │  │shard │  │shard │  │shard │  │shard │        │shard │   │
        │  │  0   │  │  1   │  │  2   │  │  3   │        │  7   │   │
        │  └──────┘  └──────┘  └──────┘  └──────┘        └──────┘   │
        │                                                             │
        │  内部通信: NCCL (All-Gather, Reduce-Scatter, All-Reduce)   │
        └─────────────────────────────────────────────────────────────┘


为什么是 1 个 Worker？
───────────────────────────────────────────────────────────────────────────
- 单机 8 卡通过 NCCL 直接通信，不需要跨进程
- 1 个 Worker 管理 8 个 GPU，内部用 FSDP 分片
- 显存复用：Actor、Rollout、Ref 共享 GPU，不同时使用
```

### 3.2 双机 16 卡场景

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    双机 16 卡，2 个 Worker                               │
└─────────────────────────────────────────────────────────────────────────┘

                    ┌─────────────────────────────────────┐
                    │         Driver (Ray 主进程)          │
                    └─────────────────────────────────────┘
                                     │
                    ┌────────────────┴────────────────┐
                    │                                 │
                    ▼                                 ▼
        ┌─────────────────────────┐     ┌─────────────────────────┐
        │   FSDPWorker 0          │     │   FSDPWorker 1          │
        │   (机器 0, GPU 0-7)     │     │   (机器 1, GPU 8-15)    │
        │                         │     │                         │
        │   GPU 0-7:             │     │   GPU 8-15:            │

                    │                                 │

                              跨机器通信


关键点:
───────────────────────────────────────────────────────────────────────────
- 每个 Worker 管理一台机器的 8 卡
- FSDP 跨 Worker 分片：16 卡共同存储完整模型
- 每个 Worker 内部有独立的 Rollout (vLLM)
```

## 四、Worker 内部如何协同工作？

### 4.1 时分复用显存

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    三合一组件的时分复用                                   │
└─────────────────────────────────────────────────────────────────────────┘

时间轴:
───────────────────────────────────────────────────────────────────────────

T1: Rollout 阶段 (生成 response)
    ┌─────────────────────────────────────────────────────────────┐
    │  vLLM Rollout 使用显存                                       │
    │  - 加载权重 (从 FSDP 同步)                                   │
    │  - KV Cache                                                 │
    │  - 生成 responses                                           │
    │                                                             │
    │  Actor/Ref: 休眠状态 (权重 offload 到 CPU 或释放)            │
    └─────────────────────────────────────────────────────────────┘
                              │
                              ▼
T2: 训练阶段 (计算梯度、更新)
    ┌─────────────────────────────────────────────────────────────┐
    │  FSDP Actor 使用显存                                         │
    │  - All-Gather 收集权重                                       │
    │  - 前向/反向计算                                             │
    │  - Reduce-Scatter 同步梯度                                   │
    │                                                             │
    │  Rollout: sleep() 释放显存                                   │
    │  Ref: 需要时加载 (计算 KL 散度)                               │
    └─────────────────────────────────────────────────────────────┘
                              │
                              ▼
T3: 下一轮 Rollout...
    回到 T1

显存复用效果:
───────────────────────────────────────────────────────────────────────────
- 不需要同时放下 Actor + Rollout + Ref 三份权重
- 只需要 max(Actor显存, Rollout显存, Ref显存)
- 节省约 2/3 显存！  只需要存一份显存就够，但其实actor和ref都要存
```

### 4.2 权重同步流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Actor → Rollout 权重同步                              │
└─────────────────────────────────────────────────────────────────────────┘

代码位置: verl/workers/sharding_manager/fsdp_vllm.py

Step 1: FSDP Actor 权重分片存储
───────────────────────────────────────────────────────────────────────────
  GPU 0: W_shard_0
  GPU 1: W_shard_1
  ...
  GPU 7: W_shard_7

Step 2: All-Gather 收集完整权重
───────────────────────────────────────────────────────────────────────────
  每个 GPU 都得到完整权重 W = [W_shard_0, ..., W_shard_7]
  
  代码: actor_weights = get_model_state_dict(self.module)

Step 3: 按 TP 切分，加载到 vLLM
───────────────────────────────────────────────────────────────────────────
  如果 TP=2:
    GPU 0,1: 各存 W 的一半 (左/右)
    GPU 2,3: 各存 W 的一半
    ...
  
  代码: model.load_weights(actor_weights)

Step 4: vLLM 推理
───────────────────────────────────────────────────────────────────────────
  Tensor Parallel 并行计算

Step 5: vLLM sleep，释放显存给 Actor 训练
───────────────────────────────────────────────────────────────────────────
  代码: self.inference_engine.sleep(level=1)
```

## 六、回答你的问题

### Q1: "一个 Worker 是一张卡吗？"

**不是！** Worker 是一个进程，管理一组 GPU（通常是一台机器的所有 GPU）。

- 单机 8 卡 → 1 个 Worker，管理 8 个 GPU
- 双机 16 卡 → 2 个 Worker，每个管理 8 个 GPU

### Q2: "三合一是什么意思？"

一个 Worker 内部同时包含三个组件：
1. **Actor** (FSDP): 用于训练，计算梯度，更新参数
2. **Rollout** (vLLM): 用于推理，生成 response
3. **Ref Policy** (FSDP): 参考模型，计算 KL 散度

它们**时分复用**同一组 GPU，不是同时运行，而是轮流使用显存。

### Q3: "Worker 内部的分布式是怎样的？"

```
Worker 内部:
───────────────────────────────────────────────────────────────────────────
- FSDP Actor: 所有 GPU 分片存储权重 (world_size = 8)
- vLLM Rollout: 按 TP 分组，每组内并行推理 (TP = 2, dp = 4)
- FSDP Ref: 同 Actor，分片存储

跨 Worker:
───────────────────────────────────────────────────────────────────────────
- FSDP: 所有 GPU 共同分片 (world_size = 16)
- 每个 Worker 内的 Rollout 独立处理不同数据
```

### Q4: "vLLM 是单独的吗？"

是的！vLLM Rollout 是 Worker 内的一个**独立组件**：
- 有自己的推理引擎
- 权重从 FSDP Actor 同步过来
- 用 Tensor Parallel 做推理
- 用完后 sleep 释放显存

```yaml
trainer:
```

```
1 个 Worker, 8 个 GPU
```

## 八、Worker + Ray 分布式调度的好处

### 8.1 传统做法的问题

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    传统做法：手动管理三个模型                                  │
└─────────────────────────────────────────────────────────────────────────────┘

假设你有 2 台机器，每台 8 卡，需要训练 Actor、Ref、Rollout 三个模型


【方案一：三台机器各放一个模型】
─────────────────────────────────────────────────────────────────────────────

  机器 A (8卡)        机器 B (8卡)        机器 C (8卡)
  ┌─────────┐        ┌─────────┐        ┌─────────┐
  │  Actor  │        │   Ref   │        │ Rollout │
  │  训练用  │        │  参考用  │        │  推理用  │
  └─────────┘        └─────────┘        └─────────┘

  问题：
  ❌ 需要 3 台机器才能跑（资源浪费）
  ❌ 每次通信都要跨机器
  ❌ Actor 训练时需要 Ref 的输出 → 必须等机器 B 返回
  ❌ Actor 训练时需要 Rollout 的输出 → 必须等机器 C 返回
  ❌ 跨机器延迟大，训练效率低
  ❌ 手动管理进程：要在每台机器上手动启动脚本


【方案二：一台机器放三个模型】
─────────────────────────────────────────────────────────────────────────────

  机器 A (8卡)
  ┌─────────────────────────────────────────────────────────────┐
  │  Actor (8卡) + Ref (复用 Actor?) + Rollout (??)             │
  └─────────────────────────────────────────────────────────────┘

  问题：
  ❌ 7B 模型 × 3 = 21B，单机放不下
  ❌ 即使放得下，显存不够训练
  ❌ 没有统一的进程管理框架


【方案三：手动时分复用】
─────────────────────────────────────────────────────────────────────────────

  程序员手动写代码：
  
  # 步骤 1：加载 Rollout 生成
  load_rollout()
  responses = generate()
  unload_rollout()
  
  # 步骤 2：加载 Actor 计算
  load_actor()
  log_probs = compute()
  
  # 步骤 3：加载 Ref 计算
  load_ref()
  ref_log_probs = compute()
  unload_ref()
  
  # 步骤 4：训练 Actor
  train_actor()

  问题：
  ❌ 代码复杂，容易出错
  ❌ 没有统一的框架管理
  ❌ 扩展到多机更复杂
  ❌ 没有容错机制
```

### 8.2 Worker + Ray 的四大好处

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    好处一：统一进程管理                                       │
└─────────────────────────────────────────────────────────────────────────────┘

传统：手动在每台机器上启动脚本
─────────────────────────────────────────────────────────────────────────────
  ssh machine_A "python train_actor.py &"
  ssh machine_B "python run_ref.py &"
  ssh machine_C "python run_rollout.py &"
  # 手动协调进程启动顺序、端口、环境变量...


Ray：一条命令启动所有
─────────────────────────────────────────────────────────────────────────────
  ray run your_script.py
  
  Ray 自动：
    - 在每台机器上启动 Worker 进程
    - 分配 GPU 资源
    - 设置通信地址和端口
    - 管理进程生命周期
    - 失败自动重启


┌─────────────────────────────────────────────────────────────────────────────┐
│                    好处二：显存时分复用                                       │
└─────────────────────────────────────────────────────────────────────────────┘

一个 Worker 内部，三个模型共享 GPU，轮流使用：

时间轴：
─────────────────────────────────────────────────────────────────────────────

T1: Rollout 生成
┌─────────────────────────────────────────────────────────────────────────┐
│  vLLM 使用显存，Actor/Ref 处于休眠（offload 到 CPU）                      │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
T2: Actor 计算 log_probs
┌─────────────────────────────────────────────────────────────────────────┐
│  Rollout sleep 释放显存，Actor 加载使用                                  │
│  Ref 按需加载计算 KL                                                     │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
T3: Actor 训练
┌─────────────────────────────────────────────────────────────────────────┐
│  只有 Actor 在训练，其他组件休眠                                          │
└─────────────────────────────────────────────────────────────────────────┘

显存需求 = max(Actor, Rollout, Ref)，而不是三者之和

结果：7B 模型 × 3 = 21B → 只需要 ~14GB 显存（一个模型的大小）


┌─────────────────────────────────────────────────────────────────────────────┐
│                    好处三：同机通信高效                                       │
└─────────────────────────────────────────────────────────────────────────────┘

传统（三模型分三台机器）：
─────────────────────────────────────────────────────────────────────────────

  机器 A (Actor)  ←──网络──→  机器 B (Ref)
       │                           │
       │         跨机器延迟          │
       │        ~1-10ms            │
       │                           │
       └─────── 每步都要通信 ───────┘
       
  每次训练都要：
    - Actor → Ref: 发送数据，等待返回
    - 跨机器传输 14GB 权重或数据
    - 效率极低


Worker + Ray（同机内）：
─────────────────────────────────────────────────────────────────────────────

  Worker 内部 (同一台机器):

  Actor ←──NVLink──→ Ref ←──NVLink──→ Rollout

       │         同机带宽          │
       │        ~300GB/s          │
       │        延迟 ~1μs         │
       
  数据通过共享内存传输，几乎零拷贝


┌─────────────────────────────────────────────────────────────────────────────┐
│                    好处四：扩展性                                            │
└─────────────────────────────────────────────────────────────────────────────┘

从 1 台机器扩展到 N 台机器：

传统：
─────────────────────────────────────────────────────────────────────────────
  需要手动：
    - 修改每台机器的启动脚本
    - 配置 MASTER_ADDR, MASTER_PORT
    - 确保 NCCL 配置正确
    - 手动管理进程同步
    - 一台机器挂了，整个训练可能卡住


Ray：
─────────────────────────────────────────────────────────────────────────────
  只需要修改配置：

    trainer.nnodes: 1 → 2

  Ray 自动：
    - 在新机器上启动 Worker
    - 设置分布式通信
    - Worker 失败自动重启
    - 支持弹性伸缩
```

### 8.3 对比总结表

```
┌───────────────┬─────────────────────────┬─────────────────────────────────┐
│     方面      │        传统做法          │       Worker + Ray             │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 进程管理      │ 手动在每台机器启动脚本   │ 一条命令自动启动所有进程        │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 显存占用      │ 三个模型同时占用显存     │ 时分复用，只需一份显存          │
│               │ 7B×3=21GB               │ max(7B,7B,7B)=7GB              │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 通信效率      │ 跨机器网络传输           │ 同机内 NVLink/共享内存          │
│               │ 延迟 ~1-10ms            │ 延迟 ~1μs                      │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 代码复杂度    │ 手动管理加载/卸载        │ 框架自动管理                    │
│               │ 容易出错                │ 统一封装                        │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 扩展性        │ 手动配置新机器          │ 修改配置即可                    │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 容错          │ 进程挂了可能卡死        │ 自动重启失败 Worker             │
├───────────────┼─────────────────────────┼─────────────────────────────────┤
│ 资源利用率    │ 需要 3 台机器           │ 1 台机器即可                    │
└───────────────┴─────────────────────────┴─────────────────────────────────┘
```

### 8.4 Worker 的核心价值

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Worker 的核心价值                                        │
└─────────────────────────────────────────────────────────────────────────────┘

1. 【封装三合一】
   - Actor + Rollout + Ref 打包成一个 Worker
   - 不需要三台机器，不需要三个进程
   - 代码更简洁

2. 【显存时分复用】
   - 不是同时存三个模型
   - 而是轮流使用显存
   - 节省 2/3 显存

3. 【Ray 统一调度】
   - 跨机器启动进程，一行命令
   - 自动管理资源分配
   - 自动处理进程间通信
   - 自动容错重启

4. 【通信效率】
   - Worker 内部：同机 NVLink，快
   - Worker 之间：NCCL 跨机器，但只有梯度同步
   - 避免了频繁的跨机器模型调用
```

### 8.5 一句话总结

**传统做法**：三台机器各跑一个模型，跨机器调用效率低，代码复杂，资源浪费。

**Worker + Ray**：一台机器跑一个 Worker（内含三模型），时分复用显存，同机通信高效，代码简洁，易于扩展。
