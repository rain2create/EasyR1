# GRPO 训练数据流

> 简化版，只关注数据流转，不涉及分布式细节

---

## 配置参数

```
rollout_batch_size = 128      # 需要多少个不同的问题
mini_rollout_batch_size = 32  # 每次取多少个问题
rollout.n = 8                 # 每个问题生成几个回答
```

**计算关系：**
- 循环次数 = 128 / 32 = 4 轮
- 每轮生成 = 32 × 8 = 256 个样本
- 最终样本数 = 128 × 8 = 1024 个

## 完整数据流程图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           GRPO 训练数据流                                    │
└─────────────────────────────────────────────────────────────────────────────┘

                              ┌──────────────┐
                              │   训练开始    │
                              └──────┬───────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 1: 生成阶段                                                            │
│  ─────────────────                                                           │
│                                                                             │
│  循环 4 轮，每轮处理 32 个问题：                                               │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  1.1 从 DataLoader 取数据                                              │  │
│  │      - prompts: 32 个问题                                              │  │
│  │      - images: 图片数据                                                 │  │
│  │      - ground_truth: 标准答案                                          │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                     │                                        │
│                                     ▼                                        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  1.2 vLLM 生成回答                                                      │  │
│  │      - 每个 prompt 生成 n=8 个回答                                      │  │
│  │      - 输出: 32 × 8 = 256 个样本                                        │  │
│  │      - 包含: responses, old_log_probs, response_mask                   │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                     │                                        │
│                                     ▼                                        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  1.3 为每个样本生成唯一 uid                                             │  │
│  │      - 同一问题的 8 个回答共享同一个 uid                                 │  │
│  │      - 用于 GRPO 组内标准化                                             │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                     │                                        │
│                                     ▼                                        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  1.4 累积 batch                                                         │  │
│  │      - 累积 4 轮后得到 1024 个样本                                       │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  最终 batch 包含:                                                           │
│    - prompts: (1024, prompt_len)                                           │
│    - responses: (1024, response_len)                                       │
│    - old_log_probs: (1024, response_len)                                   │
│    - response_mask: (1024, response_len)                                   │
│    - uid: (1024,) - 128 个不同 uid，每个重复 8 次                           │
│    - ground_truth: (1024,)                                                 │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 2: 计算奖励                                                            │
│  ─────────────────                                                           │
│                                                                             │
│  对每个样本:                                                                 │
│    1. 解码 response → 字符串                                                │
│    2. 格式奖励: 检查是否有 <think...><boxed...> 格式                         │
│    3. 准确率奖励: 提取 <boxed> 内答案，与 ground_truth 比较                  │
│    4. 综合分数 = 0.9 × accuracy + 0.1 × format                             │
│                                                                             │
│  输出:                                                                       │
│    - token_level_scores: (1024, response_len)                              │
│    - Sparse reward: 只在回答末尾有分数，其他位置为 0                         │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 3: 重计算 log_probs                                                    │
│  ───────────────────────────                                                 │
│                                                                             │
│  用当前 Actor 模型重新计算 log_probs（确保一致性）                            │
│                                                                             │
│  输入: input_ids = prompts + responses (完整序列)                           │
│  输出: old_log_probs: (1024, response_len)                                  │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 4: 计算参考模型 log_probs                                              │
│  ───────────────────────────────                                             │
│                                                                             │
│  用冻结的参考模型计算 log_probs                                              │
│  用于计算 KL 散度，防止策略偏离太远                                          │
│                                                                             │
│  输出: ref_log_probs: (1024, response_len)                                  │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 5: 应用 KL 惩罚                                                        │
│  ─────────────────────                                                       │
│                                                                             │
│  kl = old_log_probs - ref_log_probs                                         │
│  token_level_rewards = token_level_scores - kl_coef × kl                   │
│                                                                             │
│  kl_coef = 0.01                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 6: GRPO 优势计算                                                       │
│  ─────────────────────                                                       │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  GRPO 核心: 组内标准化                                                  │  │
│  │                                                                         │  │
│  │  1. 按 uid 分组 (每个问题的 8 个回答为一组)                              │  │
│  │                                                                         │  │
│  │     问题 q1: [a1_1, a1_2, ..., a1_8]  ← 同一组                         │  │
│  │     问题 q2: [a2_1, a2_2, ..., a2_8]  ← 同一组                         │  │
│  │     ...                                                                 │  │
│  │                                                                         │  │
│  │  2. 计算组内统计量:                                                      │  │
│  │     group_mean = mean([s1, s2, ..., s8])                               │  │
│  │     group_std = std([s1, s2, ..., s8])                                 │  │
│  │                                                                         │  │
│  │  3. 标准化优势:                                                          │  │
│  │     advantage_i = (score_i - group_mean) / (group_std + eps)           │  │
│  │                                                                         │  │
│  │  示例:                                                                   │  │
│  │    组内分数: [0.1, 0.9, 0.5, 0.3, 0.7, 0.2, 0.8, 0.4]                   │  │
│  │    mean = 0.487, std = 0.284                                           │  │
│  │    advantages: [-1.36, 1.45, 0.05, -0.66, 0.75, -1.01, 1.10, -0.31]    │  │
│  │                                                                         │  │
│  │  含义:                                                                   │  │
│  │    - 正优势: 该回答比组内平均好                                          │  │
│  │    - 负优势: 该回答比组内平均差                                          │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  输出:                                                                       │
│    - advantages: (1024, response_len)                                       │
│    - returns: (1024, response_len)                                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 7: 更新 Actor (PPO 训练)                                               │
│  ───────────────────────────────                                             │
│                                                                             │
│  切分成 micro_batch 进行训练:                                                │
│                                                                             │
│  for micro_batch in batch.split(micro_batch_size):                         │
│                                                                             │
│      ┌───────────────────────────────────────────────────────────────────┐  │
│      │  1. 前向传播                                                       │  │
│      │      log_probs = actor(input_ids)                                 │  │
│      └───────────────────────────────────────────────────────────────────┘  │
│                                     │                                        │
│                                     ▼                                        │
│      ┌───────────────────────────────────────────────────────────────────┐  │
│      │  2. 计算 PPO Loss                                                  │  │
│      │                                                                     │  │
│      │      ratio = exp(log_probs - old_log_probs)                       │  │
│      │      clipped_ratio = clip(ratio, 1-0.2, 1+0.3)                    │  │
│      │                                                                     │  │
│      │      pg_loss = -advantages × ratio                                 │  │
│      │      pg_loss_clipped = -advantages × clipped_ratio                │  │
│      │      loss = max(pg_loss, pg_loss_clipped)                         │  │
│      │                                                                     │  │
│      │      # 加上 KL 损失                                                 │  │
│      │      kl_loss = mean(log_probs - ref_log_probs)                    │  │
│      │      total_loss = pg_loss + kl_coef × kl_loss                     │  │
│      └───────────────────────────────────────────────────────────────────┘  │
│                                     │                                        │
│                                     ▼                                        │
│      ┌───────────────────────────────────────────────────────────────────┐  │
│      │  3. 反向传播 + 梯度累积                                             │  │
│      │      loss.backward()                                               │  │
│      └───────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  累积完成后:                                                                 │
│    - clip_grad_norm_(max_norm=1.0)                                         │
│    - optimizer.step()                                                       │
│    - optimizer.zero_grad()                                                  │
│    - lr_scheduler.step()                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  Step 8: 循环结束                                                            │
│  ────────────────                                                            │
│                                                                             │
│  - 记录 metrics (loss, kl, grad_norm, reward 等)                            │
│  - 保存 checkpoint (每 N 步)                                                 │
│  - 验证 (每 N 步)                                                            │
│  - 进入下一个 global_step                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 数据 Shape 变化总结

| 阶段 | 数据项 | Shape | 说明 |
|------|--------|-------|------|
| 输入 | raw_data | (128,) | 128 个问题 |
| 生成后 | responses | (1024, rl) | 128×8 个回答 |
| | old_log_probs | (1024, rl) | log 概率 |
| | uid | (1024,) | 128 个 uid，每个重复 8 次 |
| 奖励计算 | token_level_scores | (1024, rl) | Sparse reward |
| GRPO | advantages | (1024, rl) | 组内标准化优势 |

## 关键概念

### 1. 为什么每个问题生成多个回答？

GRPO 需要比较同一问题的多个回答：
- 组内分数高的回答 → 正优势 → 鼓励生成
- 组内分数低的回答 → 负优势 → 抑制生成

### 2. uid 的作用

标识哪些回答属于同一问题：
- 同一 uid 的 8 个回答互相比较
- 不同 uid 的回答互不影响

### 3. Sparse Reward

只在回答末尾给奖励分数：
- `[0, 0, 0, ..., 0, 0.9]`
- 其他位置分数为 0

### 4. KL 惩罚

防止策略偏离参考模型太远：
- `reward = score - kl_coef × kl`
- kl_coef 越大，约束越强
